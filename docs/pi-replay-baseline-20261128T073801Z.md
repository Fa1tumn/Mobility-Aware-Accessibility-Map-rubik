이 기준 측정의 범위는 녹화 JPEG 디코딩, 프레임 품질 검사, 모델 추론, 구간 투표까지다. 실제 카메라 인코딩, BLE IMU, GPS 수신, Supabase 업로드는 측정 범위 밖이다.

## 간격별 결과

| 간격 | 전체 구간 | 결과 없는 구간 | 추론 프레임 (구간당 평균) | 미처리 프레임 | 읽지 못한 프레임 | 구간 처리 p95 (ms) | 결과 지연 p95 (ms) | 기준 충족 |

각 간격에 600장을 공급했다. 미처리 프레임은 공급 수에서 추론 수를 뺀 값이며, 품질 검사에서 제외된 사진, 선택되지 않은 사진, 새 사진에 밀려 읽지 못한 사진을 포함한다.

구간 처리 시간은 해당 구간의 추론 소요 시간 합계다. 결과 지연은 구간 종료부터 결과를 반환할 때까지의 시간이다. 두 지표의 p95가 모두 설정 간격보다 짧으면 기준을 충족한다.

- **1초**에서는 두 지표의 p95가 모두 1초를 넘었고, 40개 구간에서 결과 반환 지연이 1초를 넘었다.
- **2초**에서는 모든 구간이 결과를 냈고 지연도 2초 이내였다. 구간 처리 p95가 2초를 56.7ms 초과해 기준을 충족하지 못했다.
- **4초와 8초**는 각각 92장을 추론했다. 같은 120초 동안 4초는 판정 30개를, 8초는 판정 15개를 냈다. 구간 처리 p95와 설정 간격의 차이는 각각 445.6ms와 1,168.9ms였다.

프로세스 CPU는 코어 하나, 시스템 CPU는 코어 전체를 100%로 본다. 4초 설정에서 프레임당 모델 처리 시간 평균 990.9ms 중 Area 488.6ms와 Material 434.9ms가 합계의 약 93%를 차지했다. 같은 설정에서 JPEG 디코딩은 평균 20.4ms, 품질 검사는 호출당 평균 1.4ms였다.

결과의 적용 범위는 단일 녹화 구간의 120초 리플레이 조건이다. 현장 장비를 켠 상태의 성능, 장시간 열 영향, 노면 판정 정확도는 별도 측정 항목이다.

## 재현 및 원본 데이터

저장소 루트에서 아래 명령으로 같은 조건을 실행할 수 있다. 입력 녹화의 JPEG와 PyTorch 모델 체크포인트가 필요하다. [벤치마크 실행 가이드](pi-replay-benchmark.md)

```bash
SURFACE_REGION= TORCH_DEVICE=cpu python3 pi_replay_benchmark.py \
  recordings/campus_20261125T075508Z \
  --policy live --intervals 1 2 4 8 --start-s 0 --duration-s 120 \
  --cooldown-s 30 --warmup 3 --backend torch --torch-threads 2 \
  --model-dir models/area-surface-v3 \
  --output recordings/pi_replay_baseline_repeat
```
